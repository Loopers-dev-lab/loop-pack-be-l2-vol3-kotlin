# 대기열 스케줄러 배치 크기 산정 근거

## 시스템 처리량 기준

| 항목 | 값 | 근거 |
|------|-----|------|
| DB 커넥션 풀 | 50 | HikariCP 기본 설정 |
| 주문 1건 평균 처리 시간 | 200ms | 재고 차감 + 결제 처리 + 주문 저장 |
| 이론적 최대 TPS | 250 | 50 / 0.2 = 250 TPS |
| 안전 마진 (70%) | 175 TPS | 피크 시 여유분 확보 |

## 배치 크기 결정

```
목표 TPS: 175
스케줄러 실행 주기: 100ms (초당 10회)
배치 크기: 175 / 10 = 17.5 ≈ 18명
```

**100ms마다 18명씩** 토큰을 발급하여 초당 약 175명을 처리합니다.

## Thundering Herd 완화

1초에 175명을 한꺼번에 발급하지 않고 100ms 간격으로 분산 발급하여 순간 부하 스파이크를 방지합니다.

| 방식 | 동시 주문 요청 | DB 커넥션 점유 |
|------|--------------|--------------|
| AS-IS (1초 단위) | 175명 동시 | 175개 동시 점유 → 풀 고갈 |
| TO-BE (100ms 단위) | ~18명씩 | ~18개 점유 → 안정적 |

## 토큰 TTL

- TTL: **5분 (300초)**
- 근거: 주문 페이지 진입 → 결제 완료까지 일반적으로 2~3분 소요. 5분은 충분한 여유를 두면서도 미사용 토큰이 빠르게 회수되는 균형점.
- 토큰 만료 시 해당 슬롯은 자연스럽게 다음 대기자에게 넘어감.
