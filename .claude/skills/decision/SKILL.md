# 기술 의사결정 기록

## 사용법

```
/decision Redis 역직렬화 문제 해결
/decision --file round5 인덱스 설계 결정
```

## 인자

- 첫 번째 인자: 의사결정 주제 (필수)
- `--file <name>`: 기록할 파일명 지정. 미지정 시 현재 브랜치의 라운드/피처명으로 자동 생성

## 동작 절차

1. **기존 파일 확인**: `docs/note/` 아래에 해당 라운드/피처의 decisions 파일이 있는지 확인
2. **개발자 인터뷰**: 아래 항목을 순서대로 질문하여 정보 수집. 이미 대화 맥락에 있으면 생략 가능
   - 무엇이 문제였는가?
   - 원인은 무엇이었는가?
   - 어떤 대안들을 고려했는가?
   - 최종적으로 무엇을 선택했는가?
   - 왜 그것을 선택했는가?
3. **기록 작성**: 아래 포맷으로 작성하여 파일에 추가 (기존 파일이면 append, 없으면 새로 생성)
4. **확인**: 작성 결과를 개발자에게 보여주고 수정 요청이 있으면 반영

## 기록 포맷

```markdown
## N. 제목

### 문제

무엇이 문제였는지 구체적으로 기술. 에러 메시지가 있으면 포함.

### 원인

왜 이 문제가 발생했는지. 기술적 원인을 정확히 기술.

### 해결방안

| 방안 | 설명 | 장점 | 단점 |
|------|------|------|------|
| A. 방안명 | 설명 | 장점 | 단점 |
| B. 방안명 | 설명 | 장점 | 단점 |
| C. 방안명 | 설명 | 장점 | 단점 |

### 최종 선택

**A/B/C. 선택한 방안명**

(코드 예시가 있으면 포함)

### 근거

- 왜 이 방안을 선택했는지
- 다른 방안을 배제한 이유
```

## 파일 위치

- 저장 경로: `docs/note/{라운드}-decisions.md`
- 예: `docs/note/round5-decisions.md`
- 파일이 이미 존재하면 마지막 번호 + 1로 이어서 추가
- 번호는 파일 내 `## N.` 패턴에서 가장 큰 N을 찾아서 +1

## 주의사항

- 대안이 1개뿐이면 "다른 방안은 고려하지 않았는가?" 질문
- 근거가 모호하면 구체적 이유를 되물어라
- 코드 예시는 핵심 부분만 간결하게 포함
- 이미 대화에서 충분한 맥락이 있으면 인터뷰를 건너뛰고 바로 기록 작성 가능
