# phase-verify-docs: 설계 문서-코드 정합성 검증

설계 문서와 실제 코드 간의 갭을 분석하여 보고한다.
코드는 수정하지 않고, 불일치 항목만 리포트한다.

**사용 시점**: 구현 완료 후 `--phase verify-docs`로 독립 실행. 자동 파이프라인에 포함되지 않는다.

---

## 사전 준비

1. `docs/design/` 하위의 설계 문서를 Glob으로 탐색한다
2. 프로젝트의 모든 CLAUDE.md를 Glob(`**/CLAUDE.md`)으로 탐색하여 아키텍처 규칙 목록을 확보한다
3. 사용자가 특정 문서를 지정하면 해당 문서만 대상으로 한다

---

## Step 1: 문서별 검증

각 설계 문서에서 코드 참조(클래스명, 엔드포인트, 패턴, 규칙)를 식별하고,
Grep/Read로 실제 코드와 대조한다:

- **01-requirements.md**: API 명세, 도메인 규칙, 유비쿼터스 언어가 코드에 반영되었는가
- **02-sequence-diagrams.md**: 호출 흐름, 참여자(클래스), 트랜잭션 경계가 코드와 일치하는가
- **03-class-diagram.md**: 클래스 구조, 의존성, 메서드 시그니처가 실제 코드와 일치하는가
- **04-erd.md**: 테이블, 컬럼, 관계가 실제 스키마와 일치하는가

---

## Step 2: CLAUDE.md 규칙 대조

아키텍처 규칙(레이어 의존 방향, 네이밍 컨벤션 등)이 구현 코드에서 준수되고 있는지 확인한다.

---

## Step 3: 결과 보고

다음 형식으로 인라인 출력한다:

```
## [문서명]

### 검증 통과
- ✅ [항목]: 코드에서 확인됨 (파일:라인)

### 불일치
- ❌ [항목]: 문서에는 X라고 되어 있으나, 코드에서는 Y로 구현됨 (파일:라인)

### 누락
- ⚠️ [항목]: 문서에 명시되어 있으나 코드에서 찾을 수 없음

### 문서 미반영
- 📝 [항목]: 코드에 존재하나 문서에 기술되지 않음
```

---

## Step 4: 요약 테이블

마지막에 전체 집계를 출력한다:

```
## 정합성 검증 요약

| 문서 | ✅ 통과 | ❌ 불일치 | ⚠️ 누락 | 📝 미반영 |
|------|---------|----------|---------|----------|
```

---

## 규칙

- 코드를 **절대 수정하지 않는다** — 보고만 한다
- 불일치 항목에는 반드시 파일 경로와 라인 번호를 포함한다
- 판단이 모호한 항목은 "확인 필요"로 표시하고 개발자에게 넘긴다
